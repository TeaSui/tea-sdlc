---
name: reframe
description: Use when the user states a consequential plan, decision or belief and asks for an opinion, a challenge, a fresh perspective or what they are missing, or is about to commit to something expensive to undo on an untested assumption. Gives the strongest case against, the load-bearing assumption, a different framing and the cheapest check that settles it. Skip when the user only wants the task carried out.
---

Target: $ARGUMENTS

When no target is given, use the position the user currently holds in this conversation, and restate it in one sentence first so they can correct it.

1. **Strongest case against** — argue it the way someone who holds the opposite view, and is right, would. Use the specifics already known here (code, numbers, constraints); a generic pros-and-cons list does not count.
2. **Load-bearing assumption** — the one belief that makes the current view wrong if it is false. Say what is actually known about whether it holds.
3. **A different frame** — restate the problem so that a different solution becomes the obvious one: a different goal, a different constraint treated as fixed, a different time horizon, or not solving it at all.
4. **Cheapest check** — the smallest experiment, query or question that would tell the two views apart. Run it when it is read-only and in scope; otherwise describe it.
5. **Verdict** — which view you hold after this, and how firmly. If the original view survives, say so plainly. Do not manufacture a disagreement, and do not split the difference to be agreeable.
